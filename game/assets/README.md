# Lastlight Expanse game assets (Phase D2)

Game-specific assets only; the engine pipeline is documented in `docs/guide/ASSETS.md` and
`docs/guide/MODELING.md`. Art rules: GDD §3 (`docs/GDD/Lastlight_Expanse_GDD_v1.1.md`) and
`docs/ART_DIRECTION.md`.

```
assets.json            registry: palette + "glow" sub-palette, defaults, budgets, entries
palette.png            master palette (muted, faded post-war colours, GDD §3)
palettes/glow.png      "glow" sub-palette: neutral/warm lights, emergency lens, screens, exit signs
models/*.glb           modules (registry ids = file names): 27 Blockbench-style, 1 Blender-style
textures/signs/*.png   merchant and room signs (32x32)
materials/*.material.json  sign materials (pixel-art sampling)
prefabs/*.prefab.json  ceiling_lamp (overhead LED + light), wall_light_unit (sconce + light),
                       room_sign, merchant_stall (counter, two shelves, sign)
levels/bunker.scene.json   the static bunker (GDD §10), default level of the game
colliders.json         collision boxes per module (temporary, used by --explore)
sources/blockbench/    .bbmodel sources of real Blockbench exports (none yet)
sources/blender/       .blend sources of real Blender exports (none yet), textures/ beside them
```

## Design (revised D2): modern underground shelter

A maintained, operational military / civil-defence shelter for long-term survival: 4 m
planning grid, 4 m wide main corridor (60 m long) with floor guidance lines, 3.6 m clear
height, reinforced 0.3 m walls with 0.5 m pilasters, concrete ceiling beams every 4 m, a
suspended cable tray, vents, neutral linear overhead lights, warm wall lights, lit exit signs
(always on), emergency lights (props, lit from D7), room and merchant signage, sliding doors
(2.0 m openings) and wide 2.8 m openings for the merchant zones and the common area.
Rooms: dormitory 12×8 m (7 bunks), locker room 8×8 m (20 private lockers), common area
24×12 m, generator room 16×8 m (two generator sets, distribution panels), five merchant
zones 12×8 m each, airlock 8×12 m with the blast-door arch, exit passage with stairs to the
surface. Palette: GDD §3 muted colours, clean surfaces, subtle wear only.

## Greybox (generated)

Every file above except `assets.json` and the READMEs (and including `colliders.json`) is generated by
`game/tools/make_greybox_kit.py` (stdlib Python, deterministic bytes; ctest
`tools.greybox_kit_up_to_date`). The script is the source of the generated modules, so they
have no `.bbmodel`/`.blend`. "Blockbench-style" and "Blender-style" describe the glTF
structure the script writes (generator string, per-face UVs, NEAREST samplers; smooth normals
and tangents for the arch). They are not real exports and do not prove compatibility with
the tools. Emissive lamp and screen materials are written into the glTF by the script; real
Blockbench exports may need them added differently.

Regenerate and re-register:

```bash
python3 game/tools/make_greybox_kit.py
python3 game/tools/make_greybox_kit.py --import-commands   # prints the commands below
python3 tools/zodar.py import game/assets
python3 tools/zodar.py import game/assets/materials/... game/assets/prefabs/...   # ids of their own
python3 tools/zodar.py import <architecture modules> --class architecture
python3 tools/zodar.py import <lamp, emergency_light, terminal> --sub-palette glow
python3 tools/zodar.py assets check -- --registry game/assets/assets.json --strict
```

Registry defaults: models `sampling: pixelArt`, `compile: false`, `class: prop`. Budgets
(triangles): prop 1500, architecture 3000, character 6000. `compile` stays off in D2: compiled
KTX2 caches (`*.zodar/`) are not committed (`.gitignore`), and a strict check of entries with
`compile: true` would warn about missing outputs in every fresh checkout; the 32x32 textures
get runtime mips instead.

## Replacing a module with a real export

1. Model it to the module's size and origin (see `MODULES` in the generator; 2 m grid, 3 m
   ceiling, walls 0.25 m thick centred on grid lines, props on the floor facing +z).
2. Export to `models/<module>.glb` (same file name) with the settings in `MODELING.md`.
3. Commit the source next to it: `sources/blockbench/<module>.bbmodel` or
   `sources/blender/<module>.blend` (+ `sources/blender/textures/*.png`).
4. Remove the module from `MODULES` in the generator (so `--check` stops expecting it),
   run `zodar.py import models/<module>.glb` and the strict check. Without an entry in
   `colliders.json` the exploration mode uses the model's bounds as one collision box (fine
   for props; architecture with openings needs explicit boxes until Collider components).
5. In a Debug build with the game running, the level picks up the new file (hot reload).

## Source-file policy (regular Git, no Git LFS)

`.blend` files: compressed saves (*File > Save > Compress*), textures not packed, at most
20 MiB each; Blender backups (`*.blend1`, `*.blend2`) are ignored and rejected. ctest
`tools.game_source_sizes` (`game/tools/check_source_sizes.py`) enforces this. No other file
type has a size limit there; `.glb`/PNG limits come from the asset check (texture sizes,
triangle budgets, bounds).
